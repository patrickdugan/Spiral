A Bitcoin hedge that settles itself.

SatsHedgeZero's inverse BTC/USD contract, first run as it is on a private Signet, then moved onto research consensus rules (TXCOMMIT, OP_CAT, P2MR, OP_CHECKSIGFROMSTACK). The oracle's signatures are checked in script, and the payout is bound to the transaction. Positions change hands on-chain with one signature and no counterparty.

Not on any public network. These rules run only in a patched Core started with -keylessresearch on a custom-challenge Signet. On stock rules every one of these spends is anyone-can-spend, and the stock node in every run proves that by forking.

01

The prototype, unchanged, on a private Signet

SatsHedgeZero's own live flow (shz testnet4-live), pointed at the lab's miner node: three DLC fundings, one pre-signed 3-input, 4-output collated clearing, and two 1-sat shave probes against the mempool.

02

Settlement by script

The contract maths is ported from Rust and checked against the crate's own test vectors. SHZ's dyadic compression cuts the 220 possible prices into ranges. Each range becomes one leaf that checks only the oracle digits it needs. Move across the chart to see which leaf would settle.

03

Owners inside the output

K1 let an owner sign an off-chain assignment, so the same position could be sold twice. K2 puts the owners into the output's own tree. Every leaf rebuilds the output from the claimed owners and binds it through TXCOMMIT, so a stale owner list cannot spend. A transfer leaf lets one owner, alone, move the coin to the same contract with only their key replaced.

04

A netted book in one keyless transaction

SHZ funds its three-trade triangle together and clears it cooperatively. Here the three trades share one output: leaves over a joint price partition, each paying every party their net total. At $125,000 that is exactly the prototype's clearing, with no signatures.

05

Every trial

Each trial is one hand-built block submitted to three regtest validators: the patched node with the rules on (new), the same binary with them off (old-flag), and stock Core (old-stock). A soft fork shows up as rejected by new and accepted by both old nodes.

Evidence

    Still open

    • Netting trades that were funded separately needs 64-bit amount arithmetic or input introspection.
    • A book transfer moves a party's whole book; one trade cannot be sold out of it.
    • Amounts stay below 231 sats (about 21 BTC), because the transfer fee uses 4-byte script numbers.
    • Until a transfer confirms, two conflicting transfers race like any double spend.
