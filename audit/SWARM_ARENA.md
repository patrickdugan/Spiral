# Swarm Arena: the actual cross-examination

September 11, 2026. Baseline a0a3140. This is a chronological reconstruction of
actual reviewer tasks, tool results, and exchanged objections in this session.
The strongest-defense paragraphs in individual reports are explicitly analytic
reconstructions by their authors, not quotes from additional imaginary agents.
No external reviewer, author endorsement, or independent laboratory is implied.

## The participants and rules

- Algebra challenger: accepted-input safety, cut accounting, funded compilation.
- Inference challenger: pairing integrity, graph overlap, action/information
  controls, deterministic replay.
- Incentives challenger: authenticated weights, rounding, bond accounting,
  predictive demand, and external value.
- Coordinator: D-drive public-header replay, revised ledger, synthesis and QA.

Reviewers owned disjoint new directories. Original manuscript, code, data and
PDF were kept intact. Disputes had to end in a witness, a proof with a stated
domain, a narrowed claim, or an unresolved obligation. No count of agreeing
agents was treated as statistical confidence.

## Round 1: attacks on the original premises

The algebra reviewer found the repeated-triangle preflight mismatch. It then
ran 312 deliberately repeated walks, obtaining 161 partial rejections. It also
ran 2,000 ordinary simple-path controls, which passed. The initial broad
objection became an accepted-interface-domain bug, not a claim that ordinary
routing results had been corrupted. The cut reviewer similarly replaced a
simple gross-demand objection with an exact alternating-versus-grouped witness:
same demand totals, zero versus seven failures.

The incentives reviewer first tested identity-only splitting with unchanged
weights. The theorem won that bout. The review moved to independent coordinate
maxima, score selection, integer remainder allocation, and invalid settlement
records. A later rereading found that coalition productivity bonuses and missing
economic costs were already candidly disclosed. The reviewer explicitly
withdrew any novelty claim about discovering those assumptions.

The inference reviewer initially suspected topology overlap might undermine the
cluster story. It reconstructed all 37 original sample IDs. Actual overlap was
limited: among 28 holdouts, median pairwise node overlap was zero, although
182/378 pairs shared at least a node. Actual rows also had no duplicate keys or
missing policy pairs. The reviewer did not turn synthetic bad-input tests into
a false allegation about the retained CSVs.

## Round 2: the oracle objection meets a defender

The inference reviewer proved and tested matched-catalog retry/oracle trajectory
identity in the zero-balance-cost failure model. The incentives reviewer
objected to treating that as a refutation of information value: restricting an
oracle to three inspected candidates is different from letting retry spend
eight operational attempts. Online already sees eight public path descriptions.

The inference reviewer accepted the distinction. The final verdict preserves
the original privileged-information package under its executed-attempt limit.
It narrows the interpretation of generic intelligence and keeps two resource
axes. All 54 matched trajectory checks passed in the final 126-episode pinned
diagnostic, but zero oracle failed probes remains a definitional result.

An earlier exploratory run reported retry8/oracle8 success 85.7576% and 519 retry
failures. Those numbers appear in the preserved contemporaneous incentives
CROSS_EXAM.md. They are NOT the final pinned result. The final hash-seed-1 run
reports 84.79798% and 522 retry failures. Both runs supported the within-run
equivalence; mixing their totals would conceal the reproducibility issue.

## Round 3: failure to reproduce becomes the strongest new finding

When original-policy replay did not match retained records, the inference
reviewer stopped claiming an exact replay instead of silently moving on. It
ran separate processes with hash seeds 1 and 2. Sample identity and canonical
public graph/policy hashes agreed, yet generated state and catalog hashes
diverged. On the selected cell, each original routing policy delivered 105/110
versus 102/110. The code sorted raw edge orientations before normalizing them,
so iteration order changed which resource received each seeded draw.

A separate canonical-order reference made both witnesses agree at 106/110.
That reference changes the specification; it is not substituted for the old
outputs. The final pinned diagnostic still exactly reproduces only 6/72
original policy records. The paper records the mismatch and its scope rather
than blending it into the claimed intervention effect.

## Round 4: the coordinator's ledger gets hit

The coordinator proposed a resource ledger with gross reservations and
prepare/finish events. Six initial tests passed. The algebra reviewer supplied
a float direction, 1.0, which Python accepted as equal to integer 1. Settlement
then generated a float balance and raised validation after mutating state.

The coordinator accepted the finding, added an exact integer type guard, and
added seven invalid-direction regression cases. The pre-fix code hash and
failure remain in algebra/cross_examination.json. A companion parent response
explains the one-line repair and how to reconstruct the challenged version.
The historical result is not overwritten to make the revised ledger look
perfect. The reviewer also exercised 5,000 properly typed steps with no
invariant failure. This finite success is not a distributed atomicity proof.

## Round 5: D-drive evidence constrains the story

The coordinator found historical Bitcoin Core testnet4 blocks but no responsive
configured RPC endpoint. It extracted only public headers, checked testnet4
framing/hash/encoded targets, and anchored 512 headers to the last logged tip.
The algebra reviewer independently checked all hashes and 511 internal links,
then reread first/middle/last exported headers at three D-drive disk offsets.

The reviewer caught a minor receipt wording error: 512 headers are not 512
internal links. The corrected count is recorded in the critique and validation;
the original receipt bytes are retained. It also confirmed 64 nonpositive
timestamp differences. No one converted miner timestamps into observed
funding-latency data.

The incentives reviewer verified the exported hash and consumed the ordinal
depth scenarios under openly hypothetical service/cost rules. The contribution
of testnet4 is historical ordering and a clock-validity warning. The resulting
profits and funding delays are not measured on-chain events. No wallet or
transaction operation occurred.
